### 1. 📦 K8s v1.37 DRA 全景更新：Extended Resource GA、设备污点 Stable、CEL 派生属性登场

**原文标题:** Kubernetes v1.37: DRA Updates
**来源:** Kubernetes Blog | 2026-09-03（今日发布）
**链接:** https://github.com/kubernetes/website/blob/main/content/en/blog/_posts/2026/kubernetes-v1-37-dra-updates.md （源稿已合入 kubernetes/website 主分支；正式页面 https://kubernetes.io/blog/2026/09/03/kubernetes-v1-37-dra-updates/ 于今日 10:30 PT 上线）

🎯 **一句话精髓**: DRA Extended Resource 支持 GA——`example.com/gpu` 这类存量扩展资源请求无需 ResourceClaim、无需 device plugin 就能直接走 DRA 后端分配；配合 Stable 的设备污点/容忍与 Alpha 的 CEL 派生属性，DRA 正从「GPU 分配机制」进化成「设备全生命周期治理层」。

🔧 **技术栈**: Kubernetes DRA / DeviceClass / ResourceClaim / DeviceTaintRule / CEL / CDI / MIG / vGPU / KubeVirt / KEP 5004 / KEP 5055 / KEP 6080

📐 **架构/方法亮点**:
- Extended Resource 三连跳收官（1.35 Alpha → 1.36 Beta → 1.37 GA）：DeviceClass 直接声明扩展资源名，存量 Pod spec 零改动就能迁到 DRA 后端——「渐进采用」终于有了官方通路
- 设备污点与容忍转 Stable：驱动或集群级 DeviceTaintRule 给单个设备打污点 → 新 Pod 跳过该设备、在用 Pod 可被自动驱逐（除非 ResourceClaim 显式容忍）——节点级 taint/toleration 语义完整下沉到设备级，单卡维护/降级标记不再需要动整个节点
- 派生属性（新 Alpha）：用 CEL 表达式桥接厂商属性命名差异（`numa` vs `numaNode`），GPU+NIC 同 NUMA 配对不用再等厂商统一标准，还能从拓扑长串里切 ID、按容量自定义性能分层；兼容组特性让调度器前置拒绝 MIG/vGPU 不合法组合，而不是等驱动在节点准备阶段失败
- PreQueueingHint（新 Alpha）：ResourceClaim 事件过去触发全量扫描不可调度 Pod（O(N²)），现在用 pod informer index 精准命中受影响 Pod，重排队路径降到 O(1)

💡 **关键数据**: 本版 3 个特性 GA + 2 个 Beta + 7 个 Alpha；PreQueueingHint 早期基准下调度吞吐近乎翻倍；Beta 的 Workload 级 ResourceClaim 共享取代单 Claim 256 Pod 的预留上限；DRA Consumable Capacity（Beta）开始支持小数容量请求

🔗 **樱桃的调度视角**: 这是本周对 Master 最重要的一篇喵。设备污点 = 单卡故障隔离的原生解——GPU 推理集群里「一张卡 ECC 报错」终于可以像「一个节点 notReady」一样优雅处理；CEL 派生属性把拓扑感知配对从厂商标准之争里解放出来，KAI Scheduler 式拓扑调度不必再对抗驱动命名；PreQueueingHint 的 O(1) 重排队对千卡扩容场景是实打实的吞吐收益。加上 Beta 的 KubeVirt CDI 设备注入，GPU 虚拟化推理的透传链路基本凑齐了。

### 2. 📦 arXiv 论文：AInfer-PD——不拆卡池的分布式 MoE Prefill/Decode 复用，把通信安全做进框架

**原文标题:** AInfer-PD: Communication-Safe In-Place Prefill-Decode Multiplexing for Distributed MoE Rollouts
**来源:** arXiv cs.DC | 2026-09-02
**链接:** https://arxiv.org/abs/2609.00993

🎯 **一句话精髓**: Agentic RL 的 rollout 里异步轨迹让 prefill/decode 长期共存是常态而非一次性事件——AInfer-PD 给「原地 P/D 复用」补上缺失的通信隔离：跨 rank 协调 P/D 集合通信顺序、给 DeepEP 两条路径独立协议状态，在不拆分设备池、不迁移 KV 的情况下让交叉的注意力 DP/TP 与专家路径安全并发。

🔧 **技术栈**: MoE / Prefill-Decode 复用 / DeepEP / TP+DP / KV Cache / RL Rollout / AInfer / SGLang

📐 **架构/方法亮点**:
- 问题定位精准：P/D 分离（disaggregation）要独立卡池 + KV 迁移；原地复用保留共享设备与 KV 状态，但现有设计在「P 和 D 以不一致的跨 rank 顺序发出相交集合通信」+「DeepEP 的 P/D 路径共享可变协议状态」上会炸
- 设计三件套：跨 rank 的 P/D 集合通信排序协调、两条 DeepEP 通信路径状态彻底独立、保留共享权重与 KV 存储——通信安全成为框架职责而非上层应用的责任
- 细粒度边界入队：相比整 epoch 异步入队再降 8.6-19.8% 完成时间

💡 **关键数据**: 单节点 prefill 密集负载，固定工作量 rollout 完成时间较「关闭复用的同引擎」降 7.1-22.5%、较 SGLang 降 24.8-32.9%；双节点分别为 18.0-35.3% 与 18.3-31.8%

🔗 **樱桃的调度视角**: P/D 分离 vs 原地复用是推理平台的路线之争，这篇给出第三条路——「单池复用 + 框架级通信隔离」拿走大部分分离部署的收益而不付双池容量与 KV 传输的代价。对 K8s 调度器的直接含义：不维护 prefill/decode 两个资源池的配比与独立伸缩，容量规划模型可以简单一半；代价是把复杂性下沉进推理引擎，Master 选型时要看团队更愿意养哪个层面的复杂度喵。

### 3. 📦 arXiv 论文：DRLM——用因子化 PPO 做边缘 LLM 查询编排，时延降 51%、排队时延降 67%

**原文标题:** DRLM: Deep Reinforcement Learning-Based LLM Query Orchestration in Edge Environments
**来源:** arXiv cs.DC | 2026-09-02
**链接:** https://arxiv.org/abs/2609.00442

🎯 **一句话精髓**: 边缘环境下的 LLM 查询编排本质是在「模型家族 × 量化级别 × 异构设备」的组合空间里做质量-时延权衡——DRLM 用两个轻量预测器（类别条件质量估计 + 特征驱动时延预测）喂给因子化 PPO 智能体做状态感知编排，64 节点边缘集群实测推理时延最多降 51%。

🔧 **技术栈**: Deep Reinforcement Learning / PPO / LLM Serving / 边缘计算 / 模型量化 / 质量估计器 / 时延预测器

📐 **架构/方法亮点**:
- 双预测器解耦「好不好」与「快不快」：类别条件质量估计器把查询映射到语义类别再推断各模型表现；特征驱动时延预测器估计各「模型-设备」组合的推理时间——预测而非在线试错
- 因子化 PPO 智能体：质量/时延预测 + 系统实时状态（队列、负载）共同输入，输出编排决策；因子化结构应对组合空间爆炸
- 大规模实测数据集驱动：223,835 次测量覆盖 1258 个查询、6 个查询类别、8 个模型家族（32 个部署实例）、5 个量化等级、多种异构边缘设备

💡 **关键数据**: 推理时延最高降 51%、排队时延最高降 67%、精度损失控制在 8% 以内；高负载场景下时延改善达 61.4%；对比 3 个基线与 2 个 SOTA 方法

🔗 **樱桃的调度视角**: 这就是把「推理请求级调度器」RL 化——决策变量从 K8s 的 Pod 放置换成（模型, 量化, 设备）三元组，predicate/priority 换成 PPO 策略。与昨天的 vLLM semantic-router 正好拼成两层：语义路由决定「去哪个模型」，DRLM 决定「用哪个配置在哪台设备跑」，两层正交可叠加。中心化 GPU 池同样适用这套思路，尤其是多模型混部 + 多档量化共存的推理平台喵。

### 4. 📦 Metal3 遇上 KubeVirtBMC：把 KubeVirt 虚拟机当裸金属装机，单集群跑通 Ironic 全流程

**原文标题:** Metal3 meets KubeVirtBMC: Provisioning KubeVirt VMs like bare metal
**来源:** CNCF Blog | 2026-09-02
**链接:** https://www.cncf.io/blog/2026/09/02/metal3-meets-kubevirtbmc-provisioning-kubevirt-vms-like-bare-metal/

🎯 **一句话精髓:** KubeVirtBMC 给 KubeVirt 虚拟机挂上虚拟 BMC 端点（Redfish + IPMI），Metal3/Ironic 就能把 VM 当物理服务器走完整装机流程——Metal3 完全感知不到对面是虚拟机，裸金属供给链路从此有了可复现的「数字孪生」测试场。

🔧 **技术栈**: Metal3 / OpenStack Ironic / KubeVirt / KubeVirtBMC / Redfish / IPMI / CDI / cert-manager / IrSO / BareMetalHost

📐 **架构/方法亮点**:
- 转译链路清晰：Ironic 对 BMC Pod 发 Redfish 请求 → 翻译成 K8s API 调用控制 KubeVirt VM；VirtualMachineBMC CR 暴露 ClusterIP Service（80/TCP Redfish + 623/UDP IPMI），单集群即可端到端复现

### 5. 📦 arXiv 论文：别让模型写 YAML——LLM 自愈运维的确定性最小 Diff 方案

**原文标题:** Don't Let the Model Write the YAML: Deterministic, Minimal-Diff GitOps Remediation from LLM-Proposed Field Changes
**来源:** arXiv cs.DC | 2026-09-02
**链接:** https://arxiv.org/abs/2609.00227

🎯 **一句话精髓**: LLM Agent 自动修复 K8s 故障时，「让模型写整个文件或写 diff」都不安全——GNU patch 宽容模式下每 7 个 diff 就有约 1 个被静默错配且无任何错误信号；正确姿势是模型只输出「改哪个资源、哪个字段、改成什么」的结构化意图，由确定性管道完成语法层编辑。

🔧 **技术栈**: GitOps / LLM Agent / YAML 解析器节点位置标记 / Minimal Diff / 结构化意图 / K8s Manifest 自愈

📐 **架构/方法亮点**:
- 用真实 K8s manifests 实测打脸直觉：统一 diff 在严格 patch 下几乎全部失败是假象（宽容的 GNU patch 能应用 96%），真正的问题是静默错配 14-20% 且无错误信号；全文件重写则小模型损坏文件、前沿模型也非确定性（偶发丢字段/改邻居）且每次 O(文件大小)
- 意图与编辑分离：Agent 只 emit 结构化 field-change intent → 管道按 (kind, name) 索引清单 → YAML 解析器的节点位置标记定位目标标量的精确字符区间 → 只替换该区间，文件永不重新序列化
- 收益是结构性的：diff 天然最小、格式与注释全保留、编辑正确且确定、与模型能力无关、生成成本 O(1)

💡 **关键数据**: GNU patch 96% 可应用但 14-20% 静默错配（约 1/7）；全文件重写 O(file size) vs 意图方案 O(1)；「无文本生成策略对无人值守自动化是安全的」这一结论覆盖所有被测生成策略

🔗 **樱桃的调度视角**: 这是 AIOps 自愈的安全边界设计范本——「LLM 提语义、系统管语法」的职责切分可推广到一切 Agent 改基础设施的场景（Terraform、NetworkPolicy、HPA 参数）。Master 若做 K8s 故障自愈 Agent，意图-执行分离 + 最小 diff 保证审计与回滚，比让模型自由发挥安全一个数量级；配合 v1.37 Pod 证书的 workload 身份，无人值守自愈链路的信任模型就完整了喵。

### 6. 📦 Cloudflare OS 开源：能力模型 Gatekeeper 取代 MCP 宽授权，非技术员工 30 天建了 4000+ 工具

**原文标题:** Cloudflare OS：Cloudflare 基于能力模型构建的开源企业级 AI 平台
**来源:** InfoQ 中文 | 2026-09-02
**链接:** https://www.infoq.cn/article/ztbou1CqjAdzrT6GNSKV

🎯 **一句话精髓**: Cloudflare 把内部 vibe-coding 平台开源：每个应用实例（Gadget）跑在独立 V8 隔离区，能力模型 Gatekeeper 取代 MCP 的「连接即宽授权」默认——Agent 零信任启动、访问按资源逐一授权、破坏性操作强制人工审批，安全团队因此敢放手让非技术员工自由编程。

🔧 **技术栈**: workerd / V8 Isolate / Dynamic Workers / 能力安全模型（Capability-based Security）/ Gatekeeper / MCP / 零信任

📐 **架构/方法亮点**:
- 起因是真实安全事件：员工私搭需要管理员权限、能访问数十个核心系统生产 API token 的生成式 AI 工作流——先用人工「魔法 AI 邮箱」分诊摩擦点，再产品化为安全平台
- Gadget 粒度隔离：每份文档/每个应用都是独立沙箱里的独立实例，共享时 Gatekeeper 会验证接收方对该 Gadget 连接的每个资源都有直接访问权——Gadget 自身有漏洞也不会越权放大

💡 **关键数据**: Cloudflare 员工自 2026 年 5 月起内部使用；非技术人员 30 天内构建超过 4000 个定制业务工具；项目由首席架构师 Kenton Varda（Cap'n Proto 作者）主导并亲自在 Hacker News 答疑

🔗 **樱桃的调度视角**: 这是 Agent 时代多租户安全的新范本——把 K8s「权限按 Pod 收敛、默认零信任」的思路搬进 AI 工作流沙箱。Master 的推理平台同样面临「Agent 该不该拿生产凭据」的问题：Gatekeeper 模式（默认零权限 + 按资源授权 + 人审破坏性操作）可以直接抄进平台设计，比给 Agent 发长寿命 token 稳妥得多；「每 Gadget 独立实例」的隔离粒度选择也和沙箱容器/runtime 的选型逻辑同源喵。

### 7. 📦 当 AI 重写数据库负载：GPU 原生数据格式、弹性闭环与「Agent 是持续写回状态的新用户」

**原文标题:** 当 AI 开始重写负载，数据库该如何重新设计？
**来源:** InfoQ 中文（腾讯云 DBTalk 顶会论文解读）| 2026-09-02
**链接:** https://www.infoq.cn/article/rhKVS8RAdp4aVPZD0vZu

🎯 **一句话精髓**: 人大/浙大/华师大学者解读 2026 顶会趋势的共识：AI 不只带来向量/图/多模态这些新数据对象，更关键的是 Agent 成为「持续检索、推理、写回任务进度与记忆的新用户」——数据库的内核数据格式、弹性机制、评测基准都要围绕这条更长更动态的任务链路重构。

🔧 **技术栈**: GPU 原生数据格式 / L3 学习型压缩 / 向量数据库 / 压缩图更新 / 存算解耦 / Serverless 数据库 / Agent 状态管理 / Benchmark 重设计

📐 **架构/方法亮点**:
- GPU 时代「压缩率高 ≠ 算得快」：沿用 CPU 侧编码 + 跨设备搬运 + 执行时解码的老路径，压缩收益会被转换与搬运成本吃掉——L3 重新设计 GPU 原生数据格式，让学习型压缩成为能直接参与 GPU 分析计算的可执行格式
- 资源解耦 ≠ 弹性自动发生：远程访问有网络开销、新节点要状态恢复与拓扑收敛、缓存扩缩影响命中率与一致性——真正的弹性要在观测/预测/决策/执行/反馈间成闭环，在「快、稳、省」之间找控制点
- Agent 状态是新的不可回收资源：任务进度、长期记忆、执行分支、权限上下文不能随计算资源回收而丢失；评测单元也要从算子/查询升级为包含检索+推理+工具调用的完整工作流

💡 **关键数据**: 面向 AI 负载的测评至少需要覆盖 5 个方向；传统 Benchmark 以查询/事务为基本单元的假设在 Agent 任务面前失效

🔗 **樱桃的调度视角**: 「Agent 状态不可随资源回收」这个论断对 K8s 调度器同样成立——Pod 可以驱逐重建，Agent 的记忆与任务上下文不能，这正是前天 SemSpot「按语义段恢复」要解的问题在数据系统侧的镜像。Master 的推理平台上，KV Cache / 会话记忆的放置策略（会话亲和、跨驱逐持久化、分级冷热）会成为与 GPU 放置同级的调度维度，值得提前在架构里留位置喵。

## 📓 樱桃的今日学习总结

1. **DRA 正在把「节点治理」的整套器官移植给「设备治理」** — 污点/容忍、标准属性、状态可见性、兼容组——K8s 用三年把节点管理概念完整复刻到 GPU/NIC 上，设备从「计数资源」变成有健康度、有亲和性、可维护的「一等公民」。调度决策粒度从 node 级走向 device 级，是 AI 集群调度走向精细化的基础设施前提；而 PreQueueingHint 把 O(N²) 重排队压到 O(1)、吞吐翻倍，说明这个方向不只是功能补齐，连性能账都开始算了。
2. **推理调度完成三层分工：请求级路由 → 引擎级 P/D 编排 → 资源级 DRA 放置** — AInfer-PD 证明「单池原地复用 + 框架级通信隔离」能逼近分离部署收益而不付双池容量与 KV 迁移代价；DRLM 用因子化 PPO 把（模型, 量化, 设备）组合决策变成可学习的策略；加上语义路由，每一层各有目标函数且正交可组合。Master 的平台设计可以直接按这三层划边界：哪层用现成的、哪层自研，比「一体化推理平台」的叙事清晰得多。
3. **「LLM 提语义、系统管语法」正在成为 Agent 安全的通用模式** — Cloudflare OS 的 Gatekeeper（意图授权 + 确定性执行边界）与 YAML 论文的结构化 intent + 确定性字符区间替换，殊途同归：Agent 的输出永远不直接变成可执行副作用，中间必须隔一层可审计、可回滚的确定性管道。这个模式可以平移到任何「Agent 改基础设施」的场景。
4. **AI 的成本外部性开始显性定价** — OVHcloud 的 6-12 倍内存价格曲线把「AI 热潮的隐性税」变成了公开报价单，且预计持续到 2028。平台团队的成本模型需要新增两类输入：内存/存储的单价通胀曲线，以及「非 AI 负载为 AI 负载分担的成本比例」——后者将来很可能要写进 FinOps 报表喵。
