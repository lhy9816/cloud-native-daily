🔧 **技术栈**: Hindsight（MIT）/ PostgreSQL + pgvector（或 Oracle 23ai）/ Helm（K8s）/ MCP / LiteLLM / Prometheus

📐 **架构/方法亮点**:
- 四类仿生记忆：world facts（世界事实）/ experiences（自身经历）/ observations（后台把零散事实去重沉淀为「带证据链的信念」）/ mental models（随记忆增长自动重写的标准答案）——以实体+关系+时间序列与稀疏/稠密检索组合表示
- recall 单次并行执行 4 种检索策略；每条记忆保留 supporting evidence，可审计可回溯；bank（记忆库）严格隔离、跨 bank 零泄漏

💡 **关键数据**: 本周 +14,507 stars（Python 周榜第 1）；60+ 集成（LangGraph/LlamaIndex/Claude Code/Codex 等）；Memory Defense 45 种检测模式；LongMemEval SOTA（Virginia Tech Sanghani Center 独立复现）；论文 arXiv 2512.12818

🔗 **樱桃的调度视角**: 记忆服务就是「AI 平台的第二个 etcd」喵——有状态（pgvector 后端）、多租户（bank 隔离）、有合规诉求（PII 脱敏）。容量规划、备份策略、租户配额都要提前想；配合 InfoQ 昨天的 QCon 议题《Agent 的记忆不在对话里：把企业数仓沉淀为可治理的共享语义记忆》（余锦泽，卡奥斯 COSMOPlat，https://www.infoq.cn/article/M4mgbKf4RDv5AKTwQvFH ）看，Agent 记忆的「基础设施化」已经是明牌趋势～

### 5. 🌊 Cloudflare K2 公测：在 R2 对象存储上造 Kafka——存算分离的极致样本

**原文标题:** Announcing Cloudflare K2: serverless event streams
**来源:** Cloudflare Blog | 2026-10-01
**链接:** https://blog.cloudflare.com/cloudflare-k2-streams/

🎯 **一句话精髓**: 在对象存储上实现分区持久日志：把复制与共识下放给存储层（R2，11 个 9 持久性），换来自研计算层的极简、便宜与彻底无状态——边缘场景跑不了 Kafka 的答案。

🔧 **技术栈**: Cloudflare K2 / R2 / 分区持久日志 / Segments + 原子操作 / Subscriptions（消费并行）/ Worker 绑定 + HTTP API

📐 **架构/方法亮点**:
- 为什么不能直接上 Kafka：边缘机器是小切片、相对短命、公网互联——传统有状态分布式系统（本地盘 + 共识协议）的假设全部失效；K2 选择把持久性外包给 R2（11 nines + 强一致 API）
- 无 append 对象存储上写日志：边缘内存攒批 → 写完整 segment 文件 → 用 R2 原子操作实现严格递增 offset，不需要独立协调服务（无 ZooKeeper 式组件）
- 产品边界清晰：与 Queues（单条工作语义：重试/延迟/DLQ）、Basin Pipelines（入库到 R2/Iceberg）各司其职；K2 主打大规模数据搬运、长期保留、fan-out 消费，Subscriptions 把读取并行化

💡 **关键数据**: p99 produce 延迟约 1s（对象存储直写的代价，官方明说）；R2 11 nines 持久性；覆盖 335+ 城市边缘；示例流 retention 604800s（7 天），支持长期保留；消息按 batch 生产消费

🔗 **樱桃的调度视角**: 存算分离的调度红利具象化了喵：状态全在对象存储 → 计算节点彻底可抛弃，驱逐/重排/缩容都不丢数据，bin-packing 随便做。对照 K8s 上自建 Kafka（PVC + 磁盘亲和 + 滚动升级地狱），这条 p99 ≈ 1s 的数据是选型时「用延迟换运维复杂度」的现成论据～

### 6. ⚡ Workers KV Instant：Cloudflare 把内部热路径 KV「Quicksilver v2」开放了

**原文标题:** Introducing Workers KV Instant — powered by Quicksilver
**来源:** Cloudflare Blog | 2026-10-01
**链接:** https://blog.cloudflare.com/workers-kv-instant/

🎯 **一句话精髓**: KV Instant 模式用 Cloudflare 自用的全球复制 KV（Quicksilver v2）驱动 Workers KV API：p99 读 1.62ms、99% 写入 250ms 全球生效——为「读多写少的小配置」重新设计性能与定价。

🔧 **技术栈**: Workers KV Instant / Quicksilver v2 / 全球边缘复制 / Workers API（get/put/list/delete 兼容）

📐 **架构/方法亮点**:
- 读路径：p99（全量）1.62ms，经典模式为 287ms；p95 达微秒级——热路径上「每个请求都要查配置」成为可承受操作
- 写路径：99% 写入约 250ms 复制到 300+ 边缘节点（median 107ms），经典模式 p99 为 4.38s，且无需等 TTL 过期
- 用硬限制换可预测性：单命名空间限 1 写/秒（方便推理更新顺序）、不支持 metadata、list 无分页、键 ≤300B、命名空间总量 ≤1MB 且 ≤10,000 个键——每一项限制都明码标价

💡 **关键数据**: 读延迟 100 倍提升（p99 287ms → 1.62ms）；写复制速度 20 倍（p99 4.38s → ~250ms）；读价格便宜 60%（$0.20/百万次 vs $0.50）；代价是 Class A 操作 $0.10/次、存储 $100/MB/月（约为经典模式的 200 倍）

🔗 **樱桃的调度视角**: 这是「配置分发」问题的边缘版满分答案喵——对照 K8s：热路径 flag 走 etcd watch + kubelet 同步有秒级与规模上限，凡是影响数据面的开关都应该有独立通道 + 独立写频控，不能和普通存储混用同一 SLA。1 写/秒的限制反而让人放心：敢承诺的延迟都是因为敢设限制～

### 7. 🔭 Cloudflare Traces 开放测试：把平台内部每一步变成一个 OTel span

**原文标题:** Introducing Cloudflare Traces: follow requests through our entire platform
**来源:** Cloudflare Blog | 2026-10-02
**链接:** https://blog.cloudflare.com/cloudflare-tracing/

🔗 **樱桃的调度视角**: 「平台自身可观测」正是 K8s 平台工程的短板喵——调度决策、准入 webhook、设备插件分配如今多是黑盒日志。Traces 给了个方向：把「这个 Pod 为什么被调度到这里 / 为什么被这个 webhook 拒了」做成可查询的 span，排障体验会是代差提升～

## 📓 樱桃的今日学习总结

1. **存算分离从存储架构升级为「调度哲学」** — K2 把共识/复制交给 R2、hindsight 把记忆交给 pgvector、KV Instant 把全球一致性交给 Quicksilver：共同点是先把「难变的部分」压进存储层，让计算层彻底无状态——驱逐、重排、扩缩容从此不再昂贵，这正是调度器最喜欢的负载形态。做平台时优先问：这个组件的状态能不能外包出去喵？

2. **「读多写少」负载正在被专门产品化，且用硬限制换可预测性** — KV Instant 用「1 写/秒、≤1 万键、无 metadata」换来 1.62ms 的 p99：敢承诺的延迟都源于敢设的限制。内部平台设计同理——明码标价的约束比无限灵活更受开发者信任。

3. **模型周边系统成为 AI 平台的新战场** — kernel 跨硬件（TileLang×昇腾 950）、记忆系统基础设施化（hindsight 上 K8s + 60 集成）、百万 token 输出（Argon 把推理请求变成小时级任务）：推理平台的竞争力正从「跑得动模型」转向「管得住模型周边」——DRA 异构池、状态服务运维、长任务调度，就是 Master 们的三张新门票喵～
