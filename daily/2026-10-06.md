### 1. 🤖 谷歌开源 AX：把 Agent 当作「第三种负载」的 K8s 风格编排器，Go 周榜登顶

**原文标题:** 谷歌开源面向自主 AI 代理的 Kubernetes 风格编排器 AX（GitHub: google/ax）
**来源:** InfoQ 中文 / GitHub Trending Go 周榜 | 2026-09-30
**链接:** https://www.infoq.cn/article/M6BRTrsyJvUg8y0M0kyh （仓库：https://github.com/google/ax ）

🎯 **一句话精髓**: 谷歌把自主 Agent 定义为既非无状态微服务、也非 run-to-completion 批任务的「第三种负载」，用 Kubernetes 式声明式 API（Task/Workspace/Gateway/Model）+ 亚秒级检查点挂起/恢复 + Actor 多路复用，编排目标直指「每集群数十亿 Agent 任务」。

🔧 **技术栈**: AX（Apache 2.0 / Go）/ Agent Substrate 沙箱运行时 / ax.io/v1alpha1 API 组 / Redis 控制面 / ko 构建部署 / MCP / gVisor 隔离

📐 **架构/方法亮点**:
- Actor 多路复用：Agent 空闲（等模型 API、工具返回或人工输入）时保存执行状态检查点并挂起，亚秒级恢复且无冷启动，数十个 Actor 复用到共享主机工作进程——专门解决「间歇式计算」利用率低的问题
- 四个声明式原语：Task 定执行生命周期 + 沙箱 CPU/内存硬边界；Workspace 声明式预挂 Git 仓库/MCP 服务器/技能包（由初始化 Agent 在任务启动前装配环境）；Gateway 管出站网络白名单并注入凭据；Model 统一 LLM 配置、凭据存 K8s Secret
- CLI 刻意做成 kubectl 形状（apply/get/describe/watch/ssh/suspend/resume），控制面经 ko 部署进 ax-system 命名空间，跟随 kubectx 上下文切换集群

💡 **关键数据**: GitHub 13,108 stars、Go 周榜第 1（+2,919 stars/周）；InfoQ 报道阅读 1.5 万+；社区评价两极：基础设施工程师称赞消除 Agent 空闲期的云成本，开发者批评 K8s+CRD+容器 registry 的运维开销；安全从业者强调 gVisor 沙箱是爆炸半径的关键约束

🔗 **樱桃的调度视角**: 「占着资源的等待」变成「检查点后可驱逐的挂起」是调度器最想要的负载形态喵——AX 的 suspend/resume 与 K8s 侧 checkpoint/restore 演进完全同向，Master 关注异构池的话，Gateway 出站白名单+凭据注入就是多租户 Agent 平台的 NetworkPolicy+Secret 联动范本～

### 2. 📦 阿里云发布 Agent Sandbox：沙箱是「继 VM 和容器之后的新算力形态」

**原文标题:** Agent 不只烧 Token：为什么 Agent Sandbox 正在变得重要？
**来源:** InfoQ 中文（云栖大会报道） | 2026-09-29
**链接:** https://www.infoq.cn/article/he0zFgEyStxF9kOh70AP

🎯 **一句话精髓**: 阿里云把智能体沙箱定义为「面向智能的新型算力形态」：以 K8s Pod 为载体跑在 MicroVM 里、原生兼容 Kubernetes API，用「每分钟 10 万个沙箱 + 快速创建/休眠恢复」同时解决安全隔离与间歇执行的资源两难。

🔧 **技术栈**: Agent Sandbox / Kubernetes API / MicroVM / Pod 载体 / 池化预热 / AMD EPYC / 机密计算

📐 **架构/方法亮点**:
- 隔离设计：每个 Sandbox 以 K8s Pod 为载体再套 MicroVM 隔离环境，把模型动态生成的不可信代码收进单个执行环境；金山办公的 Sandbox 底座同样建在 K8s 体系上（「AI 越强，越要入笼」）
- 生命周期双管齐下：快速创建（模板创建/冷启动 P99<180ms，资源池预热后热启动 P99<20ms）+ 深休眠唤醒（P99<600ms）——直接回答「Agent 等模型时占着 CPU/内存付费 vs 销毁丢状态」的两难
- 负载画像清晰：Agent 下一步调用什么工具、跑多少轮由模型动态决定，大量任务间歇执行、高频等待——传统「长期微服务 + 离线 Job」两套调度体系都不适配；编排/Tool Calling/RAG/状态管理大量落在 CPU 侧

💡 **关键数据**: 每分钟创建 10 万个沙箱；模板创建/冷启动 P99 < 180ms；池预热后热启动 P99 < 20ms；深休眠唤醒 P99 < 600ms；阿里云研发副总裁吴结生在云栖主论坛发布

🔗 **樱桃的调度视角**: 每分钟 10 万沙箱 ≈ 秒级 1,666 次沙箱创建/销毁，K8s 原生调度器根本扛不住这个 churn 喵——答案一定是节点本地池化预热（20ms 热启动的代价是常驻资源池）+ 休眠代替销毁。这和 AX 的 actor 挂起是同一命题的两个工程解：Agent Infra 的调度层正在被重写～

### 3. 🖥️ IDC 算力评估拆穿「算力荒假象」：账面算力被三个调度断层吃掉了

**原文标题:** 机房堆满算力卡，业务却还在排队？这份评估报告拆开了"算力荒假象"的破局账本
**来源:** InfoQ 中文 | 2026-09-30
**链接:** https://www.infoq.cn/article/bduvBdbgwxj6DMbNeKCC

🎯 **一句话精髓**: 企业「买得多却调不动」的算力流失在三个断层——异构芯片烟囱、整卡粗放分配、静态预留扛不住 Agent 潮汐；破局组合是细粒度切分+强隔离（HAMi）、PodGroup 成组调度、跨芯片中立抽象与多轨资源池。

🔧 **技术栈**: HAMi（CNCF 孵化级）/ GPU 虚拟化切分 / PodGroup 成组调度 / 异构芯片池化 / 三轨资源池 / Token 计量

📐 **架构/方法亮点**:
- 三个断层白描：异构芯片缺统一抽象→各建「烟囱集群」一侧排队一侧空转；整卡分配→轻量推理独占大卡造成「资源假溢出」（账面满、实大半空转）；Agent 时代调用演化为长链路、高频反思、多模型联动的脉冲式洪峰，静态分配+人工预留两头挨打
- 细粒度切分的真难点是强隔离：HAMi（范式团队主贡，今年 7 月晋升 CNCF 孵化级）攻坚动态弹性切分、消除调度过程中的资源误判、打通与批量调度引擎的协同
- 成组调度严格执行「要么全部满足，要么一个不派」（PodGroup 模式）根绝分布式训练「跑跑停停」；落地形态为「独占/共享/超分」三轨资源池——训练保稳定、高并发推理进超分池榨弹性、按拓扑与负载动态分派

💡 **关键数据**: IDC《中国 AI 算力管理平台技术能力评估，2026》六大维度评估，范式智能（前第四范式）综合第一、资源管理/运维/技术架构/交付服务四项满分；某大型政策性银行借此在两地三中心打通异构算力池；产业计量逻辑正从「卡时」转向「Token 用量」

🔗 **樱桃的调度视角**: 这篇就是 GPU 调度工作的需求说明书喵——「假溢出」对应 HAMi/vGPU 切分，「全部满足否则不派」是 Volcano/Kueue 的 gang scheduling 本职，三轨资源池=同一集群按 QoS 和超分比划分节点池；「从卡时到 Token」意味着调度优化目标要从资源占用率转向有效 token 吞吐～

### 4. 🗃️ Uber 重构 M3DB 分片放置：用固定子集群把故障影响域从 (n-1)/n 压进池内

**原文标题:** Uber 使用子集群重新设计 M3DB 分片策略，降低故障影响
**来源:** InfoQ 中文 | 2026-09-30
**链接:** https://www.infoq.cn/article/dbOwzu6l6Tr8NAhCQRC8

🎯 **一句话精髓**: 老的「任意节点可持任意分片」放置在规模化后形成全局依赖图（单节点故障影响最高 (n-1)/n）；新模型把节点划成固定大小子集群、分片空间互不重叠，副本隔离逻辑下沉到子集群内部。

🔧 **技术栈**: M3DB / 分片放置算法 / 隔离组（机架/可用区）/ 贪心重分配 / 时序数据库 / 子集群拓扑

📐 **架构/方法亮点**:
- 旧模型的隐性成本：宽松放置让一次拓扑变更波及 O(N) 节点；即便复制因子 3 + 三个可用区，单节点仍可与集群中多达 66.67% 的节点共享数据——数据恢复工作量爆炸、运维只能串行执行
- 新模型：固定大小子集群各持互不重叠的分片空间（示例：12 节点 = 2×6，各持一半分片）；子集群内部仍按隔离组把副本分散到不同机架/AZ——「先分区、区内自治」
- 扩容走贪心算法：O(S log S) 排序 + O(S×N) 模拟评估每个候选分片迁移的影响，选剩余节点负载最均匀的方案，避免二次搬移带来的额外网络传输与引导开销

💡 **关键数据**: 故障影响域从旧模型的 (n-1)/n 降至子集群内比例；RF=3 时单节点共享数据上限 66.67% → 子集群内；约束条件明码标价：实例等权重、扩容必须以子集群为单位、子集群大小须为副本因子整数倍、不支持 AddReplica 改复制因子

🔗 **樱桃的调度视角**: PodTopologySpreadConstraints 是「尽量分散」，M3DB 的教训是「尽量分散」在规模下会变成 O(N) 耦合喵——硬分区（子集群/节点池）+ 池内自治才可运维；「扩容必须整池扩」其实就是节点池伸缩粒度的设计决策，做平台时值得直接抄进设计文档～

### 5. 📊 18 个月复盘：Kafka 过滤 + Flink Operator 单作业把事件检测从 40s 压进 10s

**原文标题:** From 40 seconds to under 10: rebuilding incident detection on OpenTelemetry, Apache Kafka, and Apache Flink on Kubernetes
**来源:** CNCF Blog | 2026-09-30
**链接:** https://www.cncf.io/blog/2026/09/30/from-40-seconds-to-under-10-rebuilding-incident-detection-on-opentelemetry-apache-kafka-and-apache-flink-on-kubernetes/

🎯 **一句话精髓**: 小团队重建自动事件创建平台（AutoHOT）的完整复盘：从 90 台 VM 上的 Node.js 聚合器（40s 延迟、共享队列被邻居拖垮、成本随接入翻倍）迁移到「总线侧过滤 + Flink K8s Operator 单作业 + OTel」，并诚实公开 18 个月召回率曲线。

🔧 **技术栈**: Apache Kafka / Flink 1.20 + Flink Kubernetes Operator / OpenTelemetry (OTLP) / RocksDB / HyperLogLog / Prometheus 兼容 TSDB / Parquet

📐 **架构/方法亮点**:
- 「让总线做过滤」：服务端订阅过滤是一份 ~770 行 YAML 即代码（运营事件占总线流量 55%），只放行所辖产品/体验到专用 topic，7 天保留兼作回放窗口——直接消灭一整类扩容工作
- 热路径唯一外部调用（租户上下文富化）用 sidecar 异步化：50 万条内存缓存 + 50 并发信号量 bulkhead（超限快速失败）+ 50% 失败/慢调用率熔断——上线后零富化停顿

💡 **关键数据**: 事件到指标延迟 >40s → <10s（目标达成）；检测召回率 ~60% → 峰值 86% → 差月份回落 64%（原文原话："不是系蝴蝶结的成功故事"）；旧系统年成本 $120K→$230K 随接入增长；每日数十亿事件、10+ 云产品；共享队列噪音邻居曾两年内两次引发事故

🔗 **樱桃的调度视角**: 单个「故意只跑一个」的 Flink 作业 + autoscaler 调优被当作可靠性特性，说明有状态流作业的扩缩容本质是「savepoint 迁移」而非无状态重建喵；两次事故都源自共享队列——多租户 K8s 里队列/资源类隔离不是优化项是正确性前提～

### 6. ⚡ Cloudflare 五轮 Rust 内存优化：1.1.1.1 缓存单条目瘦身 56%，集群释放 100TB

**原文标题:** Cloudflare 将 1.1.1.1 DNS 缓存的内存占用削减了 100TB
**来源:** InfoQ 中文 | 2026-10-05
**链接:** https://www.infoq.cn/article/XWJ8G6GaFmNL74xpSgjU

🎯 **一句话精髓**: 对 1.1.1.1 解析器缓存（Big Pineapple）的 Rust 内存表示做五轮迭代：单条目 953B→420B，2500 亿条目集群释放约 100TB 工作集内存，还白赚插入吞吐 +43%、查询延迟 -19%。

🔧 **技术栈**: Rust / DNS 有线格式（wire format）/ Big Pineapple DNS 平台 / Box<[u8]> 位打包 / 连续字节缓冲

📐 **架构/方法亮点**:
- 第一轮：插入后不变的数据从 Vec/String 换成 Box<[u8]>/Box<str>，每条省 64B、集群累计省 15TB——最便宜的一刀
- 枚举装箱的教训：对大枚举变体 boxing 增加独立内存分配并破坏局部性（Reddit 评论：小规模下这些技巧得不偿失）；最终放弃枚举，记录按 DNS 有线格式存进连续字节缓冲，常用记录类型可直接拷进响应
- 其他：布尔字段位打包成位标志；省略与查询域名相同的 owner name，从缓存键重建

💡 **关键数据**: 单条目 953B → 420B（-56%）、内存分配 1.1KB → 461B；p99 每实例驻留 9.3GB → 5.3GB、p90 6.5 → 3.8GB；插入吞吐 +43%、查询延迟 -19%；集群释放 ~100TB；任意时刻缓存 >2,500 亿条目；2026-05-18 至 07-06 全量生产部署

🔗 **樱桃的调度视角**: 对缓存节点来说「内存表示密度 = 算力」——省下的 100TB 直接变成不花钱的缓存容量喵。同一思路在 GPU 上的版本就是推理集群的 KV cache 压缩（PagedAttention 之于 vLLM）：密度优化是除「买卡」和「超分」之外第三条扩容路径～

### 7. 🧭 Cloudflare 开源决策模型 Clef：非自回归出结构化决策，Clef-flash 中位延迟 38.8ms

**原文标题:** Introducing Clef: our open-source decision models, and new RL fine-tuning platform
**来源:** Cloudflare Blog | 2026-10-01
**链接:** https://blog.cloudflare.com/clef-decision-models/

🎯 **一句话精髓**: 基于 Qwen 底座的决策模型 Clef/Clef-flash（Apache 2.0 开源于 Hugging Face）：prefill-only 一遍 + 并行 schema 打分，决策步完全非自回归——中位延迟 38.8ms（对比 Jev 524.1ms），可放进 Agent 热路径，同日上线 RL 微调产品。

🔧 **技术栈**: Clef / Clef-flash / Qwen 底座 / Workers AI（边缘 GPU）/ Jev Decision Index / Apache 2.0 / RL fine-tuning / vLLM（先期 DiffusionGemma 实验）

📐 **架构/方法亮点**:
- 推理架构：一次 prefill-only pass 后直接从骨干网络内部表示导出 schema 选项，两阶段注意力路由让每个合法选项并行提取相关上下文——没有逐 token 生成，速度碾压自回归 LLM
- 规格优势：64k 上下文（Jev 仅 32k）+ 视觉编码器（可分类图像内容，Jev 仅文本）；完全 Jev-API 兼容，类型化输出带概率
- 实战对照：威胁情报域名分类（含浏览器渲染）2.2s 完成，最快的通用 LLM gpt-oss-120b 同流程 4.7s 且只返回两个分类

💡 **关键数据**: 中位延迟 Clef 209.3ms / Clef-flash 38.8ms / Jev 524.1ms，p95 238.6 / 122.4 / 536.0ms；43 项基准延迟全面领先；BFCL case exact 98.47（Jev 95.75）、BANKING77 macro-F1 94.20（Jev 79.74）、CLINC150+OOS 97.43（Jev 89.27）

🔗 **樱桃的调度视角**: 决策模型让推理平台可以按「决策/生成」分池调度喵——亚百毫秒小模型走超分池甚至边缘节点，生成类大模型走独占池；Clef-flash 38.8ms 的延迟已经低到可以内联进调度路径本身（比如准入 webhook、路由分类），「模型当调度器组件」是个值得盯的新位置～

## 📓 樱桃的今日学习总结

1. **Agent 成为第三种调度负载形态，运行时底座正在重写** — AX（有状态 actor + 亚秒检查点挂起/恢复）、阿里云 Agent Sandbox（每分钟 10 万沙箱 + 池化预热 + 深休眠唤醒）、IDC 报告（Agent 脉冲式洪峰）三条独立信号同日共振：Agent 既不是无状态微服务也不是 run-to-completion 批任务，「有状态 + 强隔离 + 间歇式计算」三特征要求新调度原语——checkpoint/restore、池预热、沙箱生命周期管理。且两家方案都把 K8s API 兼容当作默认姿势，控制面不会离开 K8s，变的是节点运行时喵。

2. **放置算法的规模定律：隔离是分区出来的，不是算出来的** — M3DB 用固定子集群把 (n-1)/n 影响域压进池内、CNCF 文章用专用 topic 摆脱共享队列噪音邻居、范式用三轨资源池画 QoS 边界：全局最优放置在规模化后耦合爆炸，工程上能活下来的解都是「先硬分区、区内自治」。做平台设计时，分区粒度（子集群/节点池/topic）本身就是最重要的 API。

3. **调度收益的三条轴：空间切分、时间复用、表示压缩** — HAMi 把整卡切成份额（空间）、AX/Sandbox 把空闲时间变成可回收资源（时间）、Cloudflare 把缓存条目压密省出 100TB（表示）。每一轴都给 10 倍级回报且互相正交——评估一个异构平台时按这三轴打分，缺哪轴补哪轴喵～
